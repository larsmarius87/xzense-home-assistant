# Xzense 0.5.28.7

## English

### Fixed: Protect manually activated Boost against fan-speed setpoint writes

The user fan-speed setpoint (GLOBAL `0x50`) is now protected when the controller reports **Boost (state 3)**.

- Before writing `0x50`, the integration requests a new controller STATUS response and waits for a new response count. If the controller reports Boost, the write is rejected; no GLOBAL write is sent.
- If the controller is disconnected, fails to return a new status, or the check fails, the fan-speed write is rejected rather than using cached status.
- The interlock is implemented in the integration so it applies to Home Assistant number controls, dashboard actions and automations.
- Boost itself uses the separate `0x08` command and **can still be turned off** from Home Assistant or the Xzense panel.
- Other settings, including Boost speed `0x4F`, retain their previous behavior. Fan-speed values remain readable during Boost.
- Automated tests cover Boost state, normal operation, missing status, disconnected Bluetooth and independence of the Boost command.
- The bundled dashboard card displays version **0.5.28.7**.

**Limitations:** A status read and a following write are not atomic at the controller. A mode change in the short interval between these operations cannot be ruled out. Physical behavior on the controller has not yet been verified after this release.

## Norsk

### Rettet: Beskyttelse mot overstyring av viftehastighet ved manuell Boost

Innstilt viftehastighet (GLOBAL `0x50`) er nå beskyttet når kontrollpanelet rapporterer **Boost (tilstand 3)**.

- Før skriving til `0x50` ber integrasjonen om en ny STATUS-respons og venter på en ny respons. Hvis panelet rapporterer Boost, avvises endringen uten at det sendes en GLOBAL-skrivekommando.
- Hvis kontrollpanelet ikke er tilkoblet, en ny status uteblir eller kontrollen feiler, blir hastighetsendringen avvist i stedet for å stole på mellomlagret status.
- Sperren ligger i integrasjonen og gjelder derfor tallentiteter, dashboard og automasjoner.
- Boost har sin egen kommando `0x08` og **kan fortsatt slås av** fra Home Assistant eller Xzense-panelet.
- Andre innstillinger, inkludert Boost-hastighet `0x4F`, fungerer som før. Hastigheten kan fortsatt leses under Boost.
- Automatiske tester dekker Boost, normal drift, manglende statusrespons, frakoblet Bluetooth og uavhengig Boost-knapp.
- Dashboardkortet viser versjon **0.5.28.7**.

**Begrensning:** Lesing av status og påfølgende skriving er ikke én atomisk operasjon i kontrollpanelet. En tilstandsendring mellom disse to operasjonene kan ikke utelukkes helt. Funksjonen er ennå ikke fysisk testet etter oppdateringen.
